# Data model (Phase 2 output)

All tables are generated by `src/generate_data.py` into `data/raw/` (Parquet; one file per month for large tables).
Dates are daily; timestamps (`*_ts`) carry minutes. IDs are integers. Same seed + scale = identical data.

Tracking granularity: **SKU** (product) → **lot** (manufacturing batch with expiry) → **pallet / LPN** (physical
pallet, moved between **locations**, addressed `ZONE-AISLE-BAY-LEVEL-SLOT`).

## Dimensions

| Table | Grain | Key columns |
|---|---|---|
| `skus` | 1 per SKU | `sku_id`, `sku_code`, `description`, `category`, `zone` (dry/chilled/frozen), `supplier_id`, `units_per_case`, `cases_per_pallet`, `unit_weight_kg`, `unit_cost`, `unit_price`, `shelf_life_days`, `min_sale_days`, `ecom_enabled`, `pick_face_location_id`, `unit_bin_location_id`, `registered_date`, `status`, `discontinued_date` |
| `suppliers` | 1 per supplier | `supplier_id`, `supplier_code`, `supplier_name`, `zone`, `nominal_lead_time_days` |
| `customers` | 1 per customer | `customer_id`, `customer_code`, `channel` (b2b/ecommerce), `region`, `route_id` |
| `locations` | 1 per address | `location_id`, `location_code`, `zone`, `aisle`, `bay`, `level`, `slot`, `location_type` (pick/reserve/overflow/unit_bin), `x_m`, `y_m`, `z_m` |
| `lots` | 1 per lot | `lot_id`, `sku_id`, `supplier_id`, `mfg_date`, `expiry_date` |
| `pallets` | 1 per pallet received | `lpn`, `sku_id`, `lot_id`, `received_date`, `initial_qty_units` |
| `promotions` | 1 per promotion | `promo_id`, `sku_id`, `start_date`, `end_date`, `discount_pct`, `communicated_to_planning_date` |
| `recalls` | 1 per recall | `recall_id`, `recall_date`, `sku_id`, `lot_id`, `units_on_hand_blocked` |

## Facts

| Table | Grain | Key columns |
|---|---|---|
| `movements` | 1 per pallet/line movement | `movement_id`, `date`, `shift`, `movement_type` (PUTAWAY, PICK, REPLENISH, RELOCATE, ADJUST_RELOCATE, WRITE_OFF_EXPIRY / COLD_CHAIN / RECALL / DAMAGE), `lpn`, `sku_id`, `lot_id`, `qty_units`, `from_location_id`, `to_location_id`, `ref_id` (PO or order line), `delay_min` |
| `receipts` | 1 per pallet at the dock | `receipt_id`, `lpn`, `po_id`, `truck_id`, `supplier_id`, `sku_id`, `lot_id`, `qty_units`, `zone`, `dock_id`, `scheduled_ts`, `arrival_ts`, `unload_ts`, `stored_ts`, `dock_to_stock_min`, `truck_temp_c`, `dock_exposure_min`, `remaining_life_pct`, `status` (ACCEPTED/REJECTED), `reject_reason`, `putaway_operator_id`, `putaway_shift`, `putaway_location_id` |
| `purchase_orders` | 1 per PO line | `po_id`, `supplier_id`, `sku_id`, `order_date`, `expected_date`, `arrival_date`, `ordered_qty_units`, `status` (RECEIVED/REJECTED/OPEN) |
| `orders` | 1 per customer order | `order_id`, `customer_id`, `channel`, `order_ts`, `promised_date`, `release_date`, `shipped_date`, `delivered_date`, `n_lines` |
| `order_lines` | 1 per order line | `order_line_id`, `order_id`, `sku_id`, `qty_ordered_units`, `qty_picked_units` |
| `returns` | 1 per returned line | `return_id`, `order_line_id`, `sku_id`, `qty_units`, `reason`, `return_date`, `disposition` (RESTOCK/SCRAP) |
| `cycle_counts` | 1 per counted address | `count_id`, `count_date`, `shift`, `operator_id`, `location_id`, `system_sku_id`, `system_qty_units`, `counted_sku_id`, `counted_qty_units`, `reason_code` |
| `inventory_daily` | SKU × lot × day snapshot | `date`, `sku_id`, `lot_id`, `qty_units`, `n_pallets` |
| `occupancy_daily` | zone × day | `date`, `zone`, `rack_positions_total`, `rack_pallets`, `overflow_pallets` |

## Integrity rules (checked by `src/validate_data.py`)

- Primary keys unique; foreign keys resolve.
- Stock conservation: for every SKU and day, `stock(t) − stock(t−1) = PUTAWAY − PICK − WRITE_OFF_*`.
- `qty_picked ≤ qty_ordered`; picked quantities equal the sum of `PICK` movements per order line.
- No sale of lots below the SKU's `min_sale_days` remaining shelf life.

## Notes for analysts

- The first 60 simulated days are a warm-up and are not recorded; stock exists on day 1 of the data.
- Master data and system records come from a real-world-like WMS: they can contain imperfections, as any real
  extract does. Profile every table before using it.
- Open POs at the end of the period have `arrival_date` empty.
- `data/legacy/` (from `src/export_legacy.py`) is a deliberately dirty copy of three tables, for cleaning practice.
